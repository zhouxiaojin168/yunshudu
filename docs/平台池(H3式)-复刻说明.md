# 平台池（海螺 H3 式）算力池 —— 本地 1:1 复刻说明

> 目标：把「45.207.214.163:3000 幻镜AI」之外的**另一种算力池做法**落地跑通 ——
> H3 那种「池子在**服务端**、客户只买 credit」的形态（即**平台池**）。
> 全部本机可跑、可验证，花费 ¥0。

---

## 0. 一句话区分三种池

| | 池① 多 Key 渠道池 | 池② Google 账号池 | **平台池（本文）** |
|---|---|---|---|
| 池在哪 | new-api 渠道配置里（key 字段拼 N 把 + polling） | 网关侧 flow-pool（OAuth 会话票） | **服务端进程内（账号资源）** |
| 客户看到什么 | 模型列表 + 按次计费 | 模型列表 | **credit 余额 + 兑换码** |
| 凭证形态 | 上游 API Key | st/at 会话票 | **上游账号（每日签到补分）** |
| 谁维护账号 | 拿货方（自己拼） | 拿货方（自己养号） | **平台方（对客户不可见）** |
| 典型站 | 45.207.214.163:3000（new-api rc.41） | 雪天 xuetianai（flow2api） | **海螺 H3（jixuwz.com:8898）** |

三者**最像的一行**：`402（余额耗尽）-> 自动换号`。
- 池①：`status_code_mapping {"402":"401"}` + `auto_ban` 只踢这一把 key -> 轮询换下一把
- 池③（本文）：`code 402 "plan balance has run out"` -> **平台池内换号重试最多 3 次** -> 仍不行 503

## 1. H3 公开文档里的原始规则（逐条抄，不是猜）

来源：`work/evidence/h3-doc.md`（148KB，2026-10-11 抓取）+ `h3/api/openapi.json`（title=`海螺 H3 出片 API`，version=2.13，28 条路径）

| # | 文档原文 | 本复刻的落点 |
|---|---|---|
| 1 | 「**平台池**：平台侧维护的账号资源。任务由调度系统挑一个余额足够的账号去打官方接口」 | `pickAccount()`：健康 && 未冷却 && `credits-held >= need`，按 `(credits-held)` **降序 = 最肥优先** |
| 2 | 「账号**每天自动签到补分**」 | `checkinTick()` 定时器（演示 60s / 生产 86400s），调上游 `/official/v2/checkin` 回写钱包 |
| 3 | 「上游要求账号余额 > 0，否则整单回 `plan balance has run out` —— 我们会在平台池里**换号重试最多 3 次**，仍不行按 503 返回」 | `runPoolTask()`：402 -> `switch_account` -> 最多 `MAX_ACCOUNT_RETRIES=3` -> 503 `upstream_balance` |
| 4 | 「`401/403` -> 账号失效，换号重试」（`ACCOUNT_EXPIRED`） | `disableAccount()` -> `healthy=0, fail_reason='ACCOUNT_EXPIRED'` |
| 5 | 「`429` -> 退避重试」 | `cooldownAccount(retry_after)` -> `cooldown_until` |
| 6 | 「`503 pool_empty`：平台池里没有可用账号」+ 队列文案「`waiting for credits (need X; fattest account holds Y)`」 | 池空返回 503 + `queued:true` + 同款文案 |
| 7 | 「单 Key **无 QPS 硬限**，但受**平台池吞吐**与 Key 额度约束」「`429 concurrency_exceeded`：并发已满（**在飞 20/20**）-> `Retry-After: 5`」 | `inflight` 闸门 `MAX_INFLIGHT=20` -> 429 + `Retry-After: 5` |
| 8 | 「Key（`sk-hl-…`）：客户凭证，由**兑换码**兑换时自动创建，**额度用完自动失效（销号）**」「额度不可追加/转移」 | `/v1/redeem` + `api_keys` 表 + `autoRevoke()` |
| 9 | 「上游要求账号余额 >= 任务成本 **x 2**（提交预占 + 结算实扣）」 | `held` 预占列 + 结算后按上游 `wallet.after` 同步 |
| 10 | 「`GET /v1/public/stats` -> `codes_total/codes_unused/codes_used/credits_pool/accounts/accounts_healthy/clips_available`（1000 credit/条）/`videos_24h`/`success_rate`」 | `/v1/public/stats` 原字段返回 |
| 11 | 「上游沙箱读不了公网 URL：400 `could not be read or decoded ... call upload_temp_url`」 | 上游模拟器对 `http(s)://` 素材直接 400，池返回 `upstream_rejected` 并**退回 Key 额度** |
| 12 | 价目：视频 **1000 credit/条**、M3 只计调用次数不扣 credit、6 个工具一口价 **0.002 credit/次**、TTS 0.1/字、音乐 150/首 | `SPECS` 表（13 个模型/工具） |

## 2. 本机架构与端口

```
客户端(任意 OpenAI SDK)
   │  Authorization: Bearer <new-api 站点 token>
   ▼
new-api (127.0.0.1:3300)                       ← 我的站（yunshudu）
   │  渠道 #12「平台池-海螺H3式(platform-pool)」type=1  base=http://127.0.0.1:9940
   │  渠道 key = 平台签发的 1 把 sk-hl-xxx（unlimited）—— 渠道里只有这一把，
   │  真正的账号池在 9940 进程内部（这就是与池① 多 Key 轮询的关键区别）
   ▼
h3-platform-pool.js (127.0.0.1:9940)           ← 本文主角「平台池」
   │  accounts 表 = 平台侧账号资源（credits / held / 签到 / 冷却 / 健康）
   │  keys 表 = 客户凭证；codes 表 = 兑换码；tasks/audit = 任务与审计
   │  402 -> 换号重试 3 次；401/403 -> 踢号；429 -> 冷却；池空 -> 503 + 排队文案
   ▼
mock-official.js (127.0.0.1:9941)              ← 模拟「官方」（钱包/签到/沙箱/402）
```

## 4. 验收结果（实测）

### 4.1 打靶 `h3pool-test.js`：**38 PASS / 0 FAIL**

| 组 | 场景 | 结论 |
|---|---|---|
| A | 预占 + 结算实扣 | 上游钱包 `{before:3000,after:2000,delta:-1000}`；Key 5000->4000；`held` 归零 |
| B | 402 `plan balance has run out` -> 换号 | attempts=2、最终落 b2；b1 钱包被同步为 0 |
| C | 3 个号全 402 -> 503 `upstream_balance` | attempts=3、audit 3 条 `switch_account`、Key 额度已退回 |
| D | 池里没有余额够的号 | 503 `pool_empty` + `queued:true` + 文案 `waiting for credits (need 2000; fattest account holds 100)` |
| E | 每日签到补分 | 签到前 503 -> 签到后账号 300 -> 出图 200；audit `daily_checkin` |
| F | 401/403 `ACCOUNT_EXPIRED` | 失效号被下线（`healthy=0, fail_reason=ACCOUNT_EXPIRED`）并换号成功 |
| G | 平台池吞吐 20/20 | 25 并发 -> **恰好 20 进 / 5 被 429**，429 带 `Retry-After: 5` |
| H | 兑换码 -> `sk-hl-` Key -> 销号 | 兑换码一次性、Key 额度用完自动 `revoked`（再请求 401 `key_revoked`） |
| I | `/v1/public/stats` | 字段齐全、免 Key、`credits_pool=4000`、`clips_available=floor(4000/1000)=4` |
| J | 沙箱读不了公网 URL | 400 `upstream_rejected` 且 Key 额度已退回 |

### 4.2 全链路 `h3pool-e2e.js`：**10 PASS / 0 FAIL**

```
① 客户端出 5 张图 -> 5/5 HTTP 200；消耗顺序 = 最肥号优先（h2 100->80）
② 把最肥号上游钱包打成 0 -> 池内 402 换号 -> 客户端仍然 200（对换号无感）；audit 记 switch_account
③ 池子清空 -> 客户端拿到 503（上游是 pool_empty，对客户口径是"稍后重试"）
④ 每日签到补分 300/号 -> 池子自动恢复 -> 客户端恢复 200
最终公开池子：accounts=3 healthy=3 credits_pool=896 videos_24h=7 success_rate=100%
```

## 5. 这套方案「能落地」的硬条件（诚实清单）

1. **账号来源**：平台池要能拿到**批量上游账号**（H3 走的是消费端账号 + 每日签到补分）。
   没有账号来源，就只剩壳子 —— 这是唯一无法在本机模拟的部分。
2. **上游接口**：H3 站的上游是 MiniMax 官方模型线（见 `docs/上游定位-H3模型谱系.md`），
   官方模型是 API-only（`Hailuo 2.3` 无开源权重），所以必须真账号真 Key。
3. **签到自动化**：`每天自动签到补分` 需要能程序化登录（或复用登录态），并处理风控。
4. **合规**：批量注册/养号 + 薅每日免费额度，属于对上游服务条款的灰区操作；
   本文只做**技术形态复刻与本地验证**，不提供账号来源、不代注册、不下单。

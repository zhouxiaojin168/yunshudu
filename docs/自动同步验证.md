# 自动同步到 GitHub（验证记录 · 终版）

> 目标：本地任何改动 → 自动提交 → 自动推送 → GitHub Pages 自动重建。
> 验证时间：2026-10-11 19:41 ~ 19:58（Asia/Shanghai）

## 1. 组成

| 部件 | 路径 | 作用 |
|---|---|---|
| 同步器 | `scripts/auto-sync.js` | `fs.watch` 递归监听 + 8s 防抖 + 300s 兜底定时 |
| 起停 | `scripts/start-autosync.ps1` / `stop-autosync.ps1` | 后台起停，PID 写 `runtime/logs/autosync.pid` |
| 计划任务 | `scripts/install-autosync-task.ps1` | 任务名 `yunshudu-autosync`，每 10 分钟 `--once` 兜底 |
| 包装器 | `scripts/autosync-once.ps1` | 计划任务环境没有 CODEX_HOME，用它注入 token |
| 日志 | `runtime/logs/auto-sync.log` | UTF-8 带 BOM，方便 PowerShell 5.1 看中文 |

## 2. 一次同步做什么

1. 重建网页快照（`scripts/build-site-json.js`）—— 网关在线时让线上数据跟着更新
2. `git add -A`
3. **敏感信息自检**（命中 `sk-` 长串 / JWT / `password:`+长值 / 私钥 → `git reset` 中止，绝不推送）
4. `git commit` → `git push`
5. 无新变化时 5 分钟内不再空推（`lastPushAt` 节流）

## 3. ★ 坑一：无限提交循环（已修复）

**症状**：静置不管，也每分钟自己冒出新提交（实测 11 分钟里冒了 12 个）。

**根因**：`/api/pricing` 的 `models` 数组顺序来自 Go map 迭代；new-api 定价缓存重建时顺序会翻一次。
旧的幂等比较只排序**对象键**、不排序**数组**，于是「同一份内容」被判定为变了 → 写文件 → 触发提交。

**修法**：`build-site-json.js` 引入 `normSnap()`

- 递归对象键排序
- `models` 按 `model_name` 排序；`model.groups` / `model.endpoints` / `channels.models` / `auto_groups` / `vendors` 一律排序
- 删除 `generatedAt`
- **比较与写入都走 `normSnap`**：语义不变 → 直接 return，绝不碰文件

**决定性测试**：人为打乱 `site.json` 与 `index.html` 内嵌快照的顺序 → 连跑两次构建 →
两次都输出 `snapshot unchanged -> skip write`，文件 mtime 完全不变。

## 4. ★ 坑二：静默窗吞掉真实改动（已修复）

**症状**：改动刚好落在同步进行中的那几秒，会被「按时间静默」的 mute 逻辑吃掉，只能等 300 秒兜底。

**修法**：**彻底废掉按时间静默**，改成精确模式：

- 同步中收到 `fs.watch` 事件 → 置 `pendingAgain = true`
- 本轮同步一结束 → 立刻补一轮（`补同步`）
- 另加 `syncing` 串行锁，避免并发双跑
- 因为 `build-site-json` 幂等，自己写自己的那一轮会在第二轮判为「没有新变化」自然收敛，不会打转

**实测**（19:49）：t=0 建文件 → t=8.5s 同步进行中再追加一笔 → 该笔在 19:49:24 被正常提交推送，**没有丢**。

## 6. 日常使用

```powershell
# 起 / 停 监听
powershell -File scripts\start-autosync.ps1
powershell -File scripts\stop-autosync.ps1

# 装 / 卸 计划任务（不需要管理员）
powershell -File scripts\install-autosync-task.ps1
powershell -File scripts\install-autosync-task.ps1 -Uninstall

# 立即同步一次
D:\node-v\node.exe scripts\auto-sync.js --once
```

token 只放**仓库外**：`%USERPROFILE%\.yunshudu\gh-token.txt` 或 `%CODEX_HOME%\work\tools\gh-token.json`。

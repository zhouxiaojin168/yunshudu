# 邮箱通道 - 域健康度矩阵（R144i）：哪个域还能收到 H3 验证码

> 结论先行：**mailfarm 那 5 个域已经收不到 H3 的码了**（H3 侧发码直接失败），必须走 tempmail 系或自建域。
> 数据来自 `scripts/mail-domain-health.js` 实测（2026-10-14 00:01），落盘 `state/mail-domain-health.json`。

## 一、判据（怎么读 H3 的返回）

H3 国际站发码接口：`POST https://hailuoai.video/v1/api/user/login/email/code?email=<addr>`（必须**直连 CN IP**，走代理会 400）

| HTTP | statusInfo.code | message | 含义 |
| --- | --- | --- | --- |
| 200 | **1200019** | The server is temporarily unavailable… | **软成功 = 邮件已发出**（R143b 实测 3 次都收到信） |
| 200 | **1200063** | Verification failed, please try again. | **发送失败**（该域被 H3 拒） |
| 200 | 1200019 + `notanemail` | 同 1200019 | 该接口**不做格式校验**，所以 1200019 是通用路径 |

→ 判据：**1200019 = 通，1200063 = 不通**。

## 三、已落地的自动化

1. **探针**：`node scripts/mail-domain-health.js`
   - 逐域发码、按 1200019/1200063 打 `ok/blocked`，写 `state/mail-domain-health.json`（含 `updated_at`）。
   - `--domains a,b,c` 自定义；`--no-control` 去掉 gmail 对照。
2. **mail-compat 1.2.0 三通道**（`COMPAT_MODE=dual`）：
   - `tempmail.plus` 系 / `mailfarm(8099)` / `imap-bridge(8098)` 三路并存；
   - **按地址域名路由上游**（`channelOf()`），`/api/mails`、`/v1/mailboxes/{a}/code` 全部自动选对上游；
   - **按健康度挑域**（`pickDomain()`）：`blocked/dead` 的域不再发号，健康文件超过 `COMPAT_HEALTH_MAX_AGE`（默认 24h）自动忽略；
   - `dual` 模式下 `/v1/recipe`、`/v1/mailboxes/acquire` 默认给 **tempmail 域**；
   - 新增 `GET /v1/channels` 看三通道 + 当前健康度。
3. **号池侧去重**：`h3-refill.js` 默认**跳过零算力号**（`credit.totalCredits=0`），落台账 `state/h3-zero.jsonl`；
   要强制带上加 `--include-zero`。（手机号去重/废号阻断早在 `pool-supply.js` 的 `state/sms-ledger.json` 里：`LEDGER_DEAD` + 号段黑名单。）

## 四、运维

- 刷新健康度：`node scripts/mail-domain-health.js`（服务器上建议每 6h 一次，已挂计划任务 `yunshudu-mail-health`）。
- 服务器配置（`services.json` → mail-compat env）：
  `COMPAT_MODE=dual`、`COMPAT_DOMAINS=mailto.plus,fexpost.com,fexbox.org,fexbox.net,tempmail.plus,…mailfarm…,qingzhou.autos`、
  `COMPAT_BRIDGE=http://127.0.0.1:8098`、`COMPAT_BRIDGE_DOMAINS=qingzhou.autos`、`COMPAT_HEALTH_FILE=C:\yunshudu\state\mail-domain-health.json`；
  `envFrom` 增加 `COMPAT_BRIDGE_KEY=IMAP_BRIDGE_API_KEY`。

## 五、边界

- H3 侧为什么拒这 5 个域，**没有拿到官方原因**，只有可复现的返回码；不做因果断言。
- `1200019` 只代表"发码请求被接受"，不代表一定进箱（进箱还取决于目标域 MTA/反垃圾）。
- 探针本身会消耗 H3 的发码配额（每个域 1 次/轮），别高频刷。

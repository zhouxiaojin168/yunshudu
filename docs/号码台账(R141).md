# 号码台账（R141）：不再为同一个号买第二次

## 1. 为什么要记账

接码平台（d1jiema）**自己声明**「随机取的号自动拉黑重复」「自动释放」，但实测：

- 回收号极多（注册成功但 **0 额度**），平台「拉黑」≠「好号」；
- 每 `getPhone` 一次就扣一次钱（0.4 元/号），平台返回什么号你**不能挑**；
- 换平台、换 `province`/`cardType`/`keyWord` 参数后，同一批脏号可能又回来一次。

所以本地记一本账做第二道闸：**这个号买过了，就别再为它花时间/等短信，也别在另一家平台重复买。**

## 2. 台账怎么记

| 状态 | 含义 | 后续动作 |
|---|---|---|
| `seen` | 刚买到、还没跑完流程 | 允许继续 |
| `ok` | 注册成功且有额度（好号） | **永不再买** |
| `zero` | 注册成功但 0 额度（废号） | **永不再买** |
| `nosms` | 收不到验证码 / 短信没发出去 | **永不再买** |
| `error` | 流程其他步骤失败 | **永不再买** |

每个号还记 `buys`（被买过几次）、`credits`、`label`、`first_at/last_at`。

- 台账文件：`state/sms-ledger.json`（`state/` 已在 .gitignore，**手机号不入库**）
- 追加流水：`state/sms-ledger.jsonl`（每条一次事件，方便以后做时间序列分析）

## 3. 去重闸怎么动作（pool-supply 注册流程里）

```
取号 -> 查台账
  ├─ 命定局号（ok/zero/nosms/error）-> 直接丢弃，不发短信、不等码，立即重取
  └─ 新号 -> 继续走 发短信 -> 收码 -> 登录/注册 -> 回读池子真实额度 -> 写台账
连续 3 次都取到废号（SUPP_SMS_MAX_TRY）-> 本轮放弃（当天平台不干净，继续只会烧钱）
```

## 4. 环境变量

| 变量 | 默认 | 说明 |
|---|---|---|
| `SUPP_SMS_LEDGER` | `state/sms-ledger.json` | 台账文件 |
| `SUPP_SMS_LEDGER_JSONL` | `state/sms-ledger.jsonl` | 追加流水 |
| `SUPP_SMS_COST` | `0.4` | 每个号的单价（元），只用于成本估算 |
| `SUPP_SMS_MAX_TRY` | `3` | 同一轮连续取到废号时最多重取几次 |
| `SUPP_SMS_PROVINCE` | 空 | 可选，限定省份（模板里写 `{province}`） |

## 5. 怎么用

```bash
# 看台账（号码 + 状态 + 额度 + 命中率 + 每张图成本）
node scripts/pool-supply.js --ledger

# 从池子把已有号一键导入台账（部署后用一次就够）
node scripts/pool-supply.js --ledger-import-pool

# HTTP（admin）
curl -H "x-admin-key: <SUPP_ADMIN_KEY>" http://127.0.0.1:9950/supply/ledger
```

`/supply/stats` 的 `config.ledger` 里也会带一份汇总（命中率 / 已花 / 每张图成本）。

## 6. 已知边界（诚实）

- **去重不能省掉「取号费」**：`getPhone` 那 0.4 元在拿到号时就扣了，台账省的是**发短信 + 最长 60s 等码**，以及「同一天反复踩同一个坑」的钱。
- 真正能压低单价的做法是：`province`/`cardType`/`keyWord` 按台账统计挑最干净的组合，或换到命中率更高的平台。
- 平台侧「自动拉黑重复号」只对**随机取号**生效；用 `phone=` 指定号不拉黑，且指定号一律以本地台账为准。

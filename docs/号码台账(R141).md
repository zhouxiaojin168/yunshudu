# 号码台账（R141）：不再为同一个号买第二次

## 1. 为什么要记账

接码平台（d1jiema）**自己声明**「随机取的号自动拉黑重复」「自动释放」，但实测：

- 回收号极多（注册成功但 **0 额度**），平台「拉黑」≠「好号」；
- 每 `getPhone` 一次就扣一次钱（0.4 元/号），平台返回什么号你**不能挑**；
- 换平台、换 `province`/`cardType`/`keyWord` 参数后，同一批脏号可能又回来一次。

所以本地记一本账做第二道闸：**这个号买过了，就别再为它花时间/等短信，也别在另一家平台重复买。**

## 2. 台账怎么记

| 状态 | 含义 | 后续动作 |
|---|---|---|
| `seen` | 刚买到、还没跑完流程 | 允许继续 |
| `ok` | 注册成功且有额度（好号） | **永不再买** |
| `zero` | 注册成功但 0 额度（废号） | **永不再买** |
| `nosms` | 收不到验证码 / 短信没发出去 | **永不再买** |
| `error` | 流程其他步骤失败 | **永不再买** |

每个号还记 `buys`（被买过几次）、`credits`、`label`、`first_at/last_at`。

- 台账文件：`state/sms-ledger.json`（`state/` 已在 .gitignore，**手机号不入库**）
- 追加流水：`state/sms-ledger.jsonl`（每条一次事件，方便以后做时间序列分析）

## 3. 去重闸怎么动作（pool-supply 注册流程里）

```
取号 -> 查台账
  ├─ 命定局号（ok/zero/nosms/error）-> 直接丢弃，不发短信、不等码，立即重取
  └─ 新号 -> 继续走 发短信 -> 收码 -> 登录/注册 -> 回读池子真实额度 -> 写台账
连续 3 次都取到废号（SUPP_SMS_MAX_TRY）-> 本轮放弃（当天平台不干净，继续只会烧钱）
```

## 4. 环境变量

| 变量 | 默认 | 说明 |
|---|---|---|
| `SUPP_SMS_LEDGER` | `state/sms-ledger.json` | 台账文件 |
| `SUPP_SMS_LEDGER_JSONL` | `state/sms-ledger.jsonl` | 追加流水 |
| `SUPP_SMS_COST` | `0.4` | 每个号的单价（元），只用于成本估算 |
| `SUPP_SMS_MAX_TRY` | `3` | 同一轮连续取到废号时最多重取几次 |
| `SUPP_SMS_PROVINCE` | 空 | 可选，限定省份（模板里写 `{province}`） |

## 5. 怎么用

```bash
# 看台账（号码 + 状态 + 额度 + 命中率 + 每张图成本）
node scripts/pool-supply.js --ledger

# 从池子把已有号一键导入台账（部署后用一次就够）
node scripts/pool-supply.js --ledger-import-pool

# HTTP（admin）
curl -H "x-admin-key: <SUPP_ADMIN_KEY>" http://127.0.0.1:9950/supply/ledger
```

`/supply/stats` 的 `config.ledger` 里也会带一份汇总（命中率 / 已花 / 每张图成本）。

## 6. 已知边界（诚实）

- **去重不能省掉「取号费」**：`getPhone` 那 0.4 元在拿到号时就扣了，台账省的是**发短信 + 最长 60s 等码**，以及「同一天反复踩同一个坑」的钱。
- 真正能压低单价的做法是：`province`/`cardType`/`keyWord` 按台账统计挑最干净的组合，或换到命中率更高的平台。
- 平台侧「自动拉黑重复号」只对**随机取号**生效；用 `phone=` 指定号不拉黑，且指定号一律以本地台账为准。

# 号码台账 R141c 加固：cardType / 省份 / 号段黑名单 / 余额可视

> 依据：d1jiema 官方 API 文档（`https://www.d1jiema.com/api.html`，本轮实抓）+ 实测余额接口

## 7. 平台 API 真实能力（先摸清，再加固）

| 功能 | 调用 | 说明 |
|---|---|---|
| 查余额 | `code=leftAmount&token=` | 只读、不计费；实测返回 `15.80` |
| 取号 | `code=getPhone&keyWord=&phone=&province=&cardType=` | `cardType` **只取 `[实卡,虚卡,全部]`**；`province` 填 APP 里的省份名 |
| 取码 | `code=getMsg&phone=&keyWord=` | keyWord 必须与短信黑括号内容匹配 |
| 释放/拉黑 | 无需调用（平台已自动释放 + 自动拉黑**随机**重复号） | 指定号不自动拉黑 |
| 历史 | `code=queryUsed&token=` | 最近 24h / 100 条；**每分钟最多 1 次**，否则封 API |

> ⚠️ 计费提醒：同一账号/IP 每 1000 次请求扣 **0.01~0.2 元**（余额查询也算）。所以余额查询加了 **60s 缓存**。

## 8. 本轮新增的四个闸

### 8.1 `cardType` 可切（新增 `SUPP_SMS_CARD_TYPE`，默认 `全部`）

- 默认**保持 `全部`，零回归**（实测好号里也有 162/170 虚拟段，一刀切改「实卡」会误伤）。
- 命中率下滑时切 `实卡` 做 A/B：`SUPP_SMS_CARD_TYPE=实卡`。
- 模板写法：把取号 URL 的 `cardType=全部` 改成 `cardType={cardType}`（本地 + 服务器已改好）。

### 8.2 省份可切（已有 `SUPP_SMS_PROVINCE`）

- API 确实支持 `province`，模板里写 `{province}` 即生效。
- 配合台账号段统计，挑「脏号率低」的省份。

### 8.3 号段黑名单（新增 `SUPP_SMS_BLOCK_SEGMENTS`）⭐

- 取号后先查前 3 位；命中黑名单 → **直接丢弃重取，不发短信、不碰海螺**。
- 连续 3 次命中黑名单 → 本轮放弃。
- `by_segment_worst` / `seg_blocked` 会出现在 `/supply/ledger` 与 `/supply/stats`。

### 8.4 余额可视（新增）

- `--sms-balance`：打印实时余额 + 当前 cardType/province。
- `/supply/stats` 的 `config.sms_balance_yuan` 也会带余额（60s 缓存）。
- 余额接口**自动从取号模板推导**（`code=getPhone` → `code=leftAmount`），**不需要在服务器额外放密钥**。

## 9. 新增用法

```bash
# 看实时余额（不花钱）
node scripts/pool-supply.js --sms-balance

# 看哪些号段最脏（附建议黑名单）
node scripts/pool-supply.js --ledger-segments

# 把最脏号段回填到黑名单（服务器 services.json 的 SUPP_SMS_BLOCK_SEGMENTS）
# 例：SUPP_SMS_BLOCK_SEGMENTS=171,165
```

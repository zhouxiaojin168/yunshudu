# 邮箱农场：为什么要一堆域名收信、原理是什么、域名在哪注册怎么操作

> 依据：对 `45.207.214.211`（实测 mailfarm）的只读勘查 + 本地/服务器复刻验证（R93~R95）。

---

## 一、一句话原理

**域名 = 你的收信地契；catch-all = 该地契下无限地址；mailfarm = 帮你批量开地址并自动把验证码抠出来。**

三个零件：

| 零件 | 作用 | 类比 |
|---|---|---|
| **域名（带 MX 记录）** | 让全世界邮件系统知道「这个域的邮件投到我这台机」 | 门牌号 |
| **catch-all（通配收信）** | `任意前缀@你的域` 都能收，不用逐个创建邮箱 | 一栋楼所有房间都收信 |
| **mailfarm** | 程序化「要地址→收信→提取验证码」 | 前台帮你拆信抄验证码 |

所以整套链路是：

~~~mermaid
flowchart LR
  A["上游站点要求邮箱注册"] --> B["注册机找 mailfarm 要地址"]
  B --> C["mailfarm 返回<br/>随机@你的域"]
  C --> D["注册机用它请求发码"]
  D --> E["上游把验证码邮件<br/>投到 你的域 的 MX"]
  E --> F["mailfarm 收信并正则提码"]
  F --> G["注册机拿码完成注册"]
  G --> H["账号进池 -> 输出算力"]
~~~

实测同款：线上 mailfarm 的 `/healthz` 直接暴露 5 个收信域 ——
`allen23.online`、`jixuwz.com`、`lopwi.cyou`、`sghd.college`、`ytu.baby`。

## 二、为什么要用「这么多」域名（不是 1 个就够了吗）

单域技术上够用（catch-all 无限地址），但**实战必须多域**，7 条原因，每条都有实测影子：

### 1. 域名会被拉黑，且拉黑是「整域连坐」
上游风控/邮件方一旦把 `ytu.baby` 标成「批量注册」，该域下**所有**地址一起废。
多域 = 单域阵亡只损失一部分产能。

### 2. 规避「同域批量注册」检测
一场注册 500 个号，若都是 `@同一域`，风控一眼看穿；拆成 5 个域 × 100 个，特征就散了。

### 3. 限量与配额按域算
有些上游/邮件商按域限速或限制新域信任度。多域 = 把配额并联。

### 4. 域信誉要「养」
新域发信/收信信誉低，容易被判垃圾。运营方拿多个域轮换，等于同时养几块地，死了还有备份。

### 5. 成本极低，冗余极便宜
`.online / .cyou / .college / .baby` 这类首年常见 **$1~3**。
实测 5 个域里 `allen.college` **DNS 都没解析**（同一张 CT 证书里躺着）= 典型的「备而未用」。

### 6. 不同上游对域名有偏好/黑名单
A 站讨厌某批域名，B 站无所谓。多域可以按站分配。

### 7. 出事可弃号弃域
单域被封 = 全线停摆；多域被封 = 扔掉最脏那个，其余照跑。

### 实测指纹（说明这些域就是同一套自动化批量搞的）

| 项 | 5 个域的实测值 |
|---|---|
| NS | **全部** `launch1.spaceship.net` / `launch2.spaceship.net`（同一个注册商，同一天批量） |
| MX | 全部 `mail.<自身域名>` |
| `mail.*` / `api.*` 的 A | **全部**指向 `45.207.214.211`（同一台收信机） |
| SPF TXT | 全部 `v=spf1 -all`（**只收不发**，标准「纯收信」声明） |
| 证书 | `sghd.college` + `lopwi.cyou` + `allen.college` 共用**同一张多域名证书** |

> 这就是「多域名收信」的真实样子：一个注册商 + 一台收信机 + N 个便宜后缀。

## 三、域名在哪注册、怎么操作

### 3.1 去哪注册

实测这批域用的是 **Spaceship**（NS = `launch*.spaceship.net`，Namecheap 的姊妹品牌）。
同类可选：

| 注册商 | 特点 |
|---|---|
| **Spaceship** | 首年超便宜、API/DNS 好使（实测运营方用的就是它） |
| **Cloudflare Registrar** | 按成本价续费、DNS 最强、**免费 Email Routing**（推荐组合） |
| Namecheap / Porkbun | 老牌、常打折 |
| 阿里云 / 腾讯云 | 国内、便宜，但域名要实名，且解析在境内 |

**省钱后缀**：`.cyou` `.online` `.college` `.baby` `.xyz` `.top`，首年常见 $1~3。

### 3.2 完整操作手册（从 0 到能收码）

**第 1 步：买域名**
注册商选一个 → 搜 `你要的后缀` → 购物车 → 结账。
要点：
- 别用你真实身份强相关的域（这是消耗品）。
- 一次买 3~5 个同后缀不同名，方便轮换。
- 打开隐私保护（WHOIS 代理）。

**第 2 步：把 DNS 托管到好用的地方**
两条路：
- 用注册商自带 DNS（Spaceship 默认就是）
- 或者改 NS 到 Cloudflare（推荐：后面要用它的免费 Email Routing）

**第 3 步：加收信记录（核心）**

| 类型 | 名称 | 值 | 说明 |
|---|---|---|---|
| `MX` | `@`（根域） | `mail.你的域`（优先级随意，如 10） | 告诉全世界：这个域的邮件投到 mail.你的域 |
| `A` | `mail` | 你的收信机公网 IP | MX 目标必须能解析 |
| `TXT` | `@` | `v=spf1 -all` | 声明「本域只收不发」，降低被当垃圾源 |

> 实测运营方就是这么配的：MX=`mail.<域>`，`mail.<域>` 的 A 全部指向同一台 `45.207.214.211`。

**第 4 步：验证**
~~~bash
nslookup -type=MX 你的域 8.8.8.8
nslookup -type=TXT 你的域 8.8.8.8
# 期望：MX 指向 mail.你的域；TXT 有 v=spf1 -all
~~~

**第 5 步：起收信服务**
把域名写进 mailfarm：
~~~powershell
$env:MF_DOMAINS="a.online,b.cyou,c.college"
$env:MF_API_KEY="<随机长key>"
.$env:MF_INGEST_KEY="<随机长key>"
# 能开 25 就开；机房封 25 就关掉走 ingest
$env:MF_SMTP_ENABLE="0"
node scripts/mailfarm-server.js
~~~

**第 6 步：接注册机**
注册流程里把「取号」换成 `type: "mail-acquire"`、「等码」换成 `type: "mail-wait"`（见 `config/pool-register.mailfarm.json`），或者直接调：

~~~bash
curl -X POST http://127.0.0.1:8099/v1/mailboxes/acquire -H "x-api-key: KEY" -d "{}"
# -> {"address":"hl8f3a...@a.online","domain":"a.online","expires_at":...}
curl "http://127.0.0.1:8099/v1/mailboxes/hl8f3a...%40a.online/code?timeout=60" -H "x-api-key: KEY"
# -> {"address":"...","code":"483920","found":true}
~~~

## 四、三种落地方式（按「机房肯不肯放 25」选）

### 方式 A：自建 SMTP，MX 直指本机（最干净，但要求 25 端口）
适用：机房放行 25（境外 VPS 多数可以，国内云/IDC 默认封）。
配置：`MF_SMTP_ENABLE=1`，`MF_SMTP_PORT=25`，MX → `mail.你的域` → 本机 IP。

### 方式 B：Cloudflare Email Routing + Email Worker（**25 被封时的正解**）副本已写好
`deploy/cloudflare/email-worker.js`

- CF 免费收信：域名托管在 CF → Email Routing → **Catch-all → Send to a Worker**
- Worker 把整封原始邮件 `POST` 到你的 `/v1/ingest`
- **完全不需要 25 端口**，收信在 Cloudflare 边缘完成

部署要点：
1. CF Dashboard → 域名 → Email → Email Routing → 启用（会自动加好 MX）
2. Routes → Catch-all address → Action = Send to a Worker → 选该 Worker
3. Worker 变量：`MF_INGEST_URL`、`MF_INGEST_KEY`（= 服务器 secrets 里的 `MAILFARM_INGEST_KEY`）
4. 服务端 `MF_DOMAINS` 要包含该域名（否则 ingest 返回 400）
5. Worker 要能从公网访问到你的 `/v1/ingest`（走已有 Cloudflare Tunnel 最省事）

### 方式 C：Postfix catch-all + 管道（自建但要会用 Postfix）
~~~
# main.cf
virtual_alias_domains = a.online, b.cyou
virtual_alias_maps = regexp:/etc/postfix/vmail.regexp
# /etc/postfix/vmail.regexp
/^(.+)@a\.online$/  mailfarm-pipe
~~~
`mailfarm-pipe` 把信件 POST 到 `/v1/ingest`。仍然需要 25 端口。

## 五、实测：25 端口到底封没封（这才是能不能走方式 A 的关键）

在本机（爷爷自有服务器 `114.66.16.225`）上做的对照实验：

| 实验 | 结果 |
|---|---|
| Windows 防火墙 | **全关**（Domain/Private/Public 都 False）→ 不是系统挡的 |
| 本机起 25 监听 | `LISTEN_25=True`（进程确实在听） |
| 从外网连 25 | **ECONNREFUSED**（连不上，日志 0 命中） |
| 换 2525 再试 | 本机 `LISTEN_2525=True`，外网仍然 **ECONNREFUSED** |
| 外部可达的端口 | 只有白名单：`80`（还被劫持）、`3000`、`8080`、`3389`、`5985`、`8899` |

**结论**：这不是你服务器的问题，是**机房的端口白名单**。→ 走方式 A 必须找 IDC 开工单解封 25（国内通常还要备案）；否则走**方式 B**。

> 顺带实测：`80` 被透明劫持到 `183.136.132.24`（Apache 提示页），所以站点也早就改走 8080 + Cloudflare Tunnel 了。

## 六、风险与红线（必须写清）

1. **只对你自有/已授权的域名和目标使用**。本仓对第三方站点只做只读勘查，从不代注册、代下单。
2. 用自有域名 + 自有服务器收信是正常技术；拿它去批量注册**你没有授权**的第三方平台，风险自负，且可能违反对方条款。
3. `v=spf1 -all` 只是声明；不要拿这套域发垃圾邮件（会被全网拉黑，且可能违法）。
4. 域名是消耗品：做好「一个域脏了就弃」的心理与成本准备。

## 4 新域接入工具：`scripts/add-maildomain.js`

```
node scripts\add-maildomain.js --domain m1.qingzhou.autos                 # 体检 + 探针（不改文件）
node scripts\add-maildomain.js --domain m1.qingzhou.autos --write          # 写入 services.json（自动备份）
node scripts\add-maildomain.js --domain m1.qingzhou.autos --cf-zone qingzhou.autos \
     --cf-token <TOKEN> --cf-routing --cf-worker yunshudu-ingest --cf-apply
```

判定口径：
- MX = `route1/2/3.mx.cloudflare.net` → **通道 A**（CF Email Routing catch-all → Worker → `POST http://114.66.16.225:8099/v1/ingest`）
- MX = `114.66.16.225` → 通道 C（直收；**服务器机房封 25，默认不可用**）
- MX = `smtp.google.com` → 通道 B（Google 邮箱 + IMAP 桥，地址必须真实存在，RCPT 要 250）
- 其它 → 警告：收信面不可控
- 命中外来域黑名单 → `REJECT`（不消耗发码配额）

其它特性：多解析器回退（本机 DNS → 1.1.1.1 → 223.5.5.5，避开 8.8.8.8 的 DNSSEC 残留 SERVFAIL）；已有 SPF/DMARC **不动**（apex 上的 Google SPF 不会被 `v=spf1 -all` 顶掉）；`--write` 幂等去重。

实测样例（`qingzhou.autos`）：NS=CF、MX=smtp.google.com、SPF 在、**DMARC 缺** → 通道 B、`DNS_OK`；CF 侧仅提议补 `_dmarc`。

## 5 收信链路（唯一的投产形态）

```
任意 xxx@新自有域
   → Cloudflare Email Routing（catch-all，MX=route1/2/3.mx.cloudflare.net）
   → Email Worker（读 raw，POST 到 http://114.66.16.225:8099/v1/ingest，带 MF_INGEST_KEY）
   → mailfarm 落库（state/mailfarm/mailfarm.jsonl）
   → mail-compat `GET /v1/mailboxes/{addr}/code` 或 `/api/mails?email=` 取码
```

要点：
- Routing → Worker **不需要 destination 验证**，正好绕开「目标邮箱不是自己的」
- 我方 8099 **公网可达**（`/v1/public/stats` = 200），**不必开 25 口**
- ⚠️ **不要**在 apex `qingzhou.autos` 开 CF Email Routing（会顶掉 Google MX）；CF 转发一律挂**子域**
- 配额纪律：单域单日发号设上限、多域轮询、新域小量预热；`blocked` 域由健康度闸门自动剔除

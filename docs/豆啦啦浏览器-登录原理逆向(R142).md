# 豆啦啦无印浏览器 · 登录原理逆向（R142）

> 样本：`E:\dola2.5\豆啦啦无印浏览器-v2.6.1-lite.exe`（75,103,229 B，Inno Setup，CompanyName=Dola，FileVersion 2.6.1.0）
> 逆向方式：全静态（安装包结构 + 实例目录取证 + DLL 元数据堆精确导出 + 远端只读探测），未修改任何第三方文件。
> 目的：拆出「登录 Dola」的真实原理，并判断哪些机制可平移到「海外海螺 H3 号池」。

## 0. 结论速览

| 问题 | 答案（已实证） |
|---|---|
| 它登录 dola 靠什么 | **邮箱+验证码自注册**（主） / **Google OAuth**（次） / 邮箱网页登录+2FA（补号） |
| 账号从哪来 | **自建邮箱域名 + 前缀续编号厂**（`取CK设置`：域名 + 端口 + 前缀≥8 + 序号 001 起） |
| 邮箱码怎么读 | ① `https://tempmail.plus/api/mails?email=&limit=5` ② 自建域名邮箱的收件 HTTP（`[取CK端口]`）③ 网页邮箱面板（`google111111.asia` 安全查看验证码，支持 `邮箱----密码----2FA` 批量 50） |

| 每天上限 | **「批量导出实例 CK」一天最多成功 20 个**（`batch-ck-export-quota.txt`） |

## 2. 三种登录/取号方式（DLL 字符串实证）

### 2.1 主路：Dola 邮箱+验证码 自注册（`DolaRegisterHttp`）
关键端点与字段（全部来自 #US 堆）：

```
GET/POST  /passport/web/email/send_code/                            email
POST      https://www.dola.com/passport/web/email/register_verify_login/   code + password
GET       /passport/account/info/v2/?aid=&sdk_source=web22&sdk_version=2.2.1-doubao.0&device_platform=web
GET       https://tempmail.plus/api/mails?email=<addr>&limit=5      mail_id / mail_list / subject
```

流程日志（原文，即状态机）：
```
开始 email=
打开首页 HTTP ...
发码成功 HTTP ...
验证码已发送，等待邮箱 X 的验证码…
正在轮询收件箱（最多 N 秒）…
仍在等待验证码邮件…
收到验证码邮件
注册成功 HTTP ... / 注册成功但没有拿到 Cookie
完成 id=...  cookie= N 条 耗时 N 秒
已经获取新账号 -> ...
```
验证码抽取正则：`验证码[^0-9]{0,10}(\d{6})` → **6 位数字**。

### 2.2 次路：Google OAuth 自动化（CDP `Runtime.evaluate` 注入脚本）
- 找按钮：遍历 `button,[role=button],a,div`，取 `innerText` ≤ 24 字符且可见的**最短**那个，匹配 `/Google\s*登录|Sign in with Google/i`
- 填邮箱：`#identifierId, input[type=email], input[name=identifier]`
- 处理谷歌验证码：`input[name=ca], input[aria-label*="听到或看到"], input[aria-label*="Type the text"]`
- 状态机：若 `location.href` 命中 `/accounts\.google\.com/` → 按页面文案返回 `'google'` / `'consent'`（`Sign in to|Continue|Google will allow` 且含 `dola.com`）/ `'captcha'` / `'dola'`
- 配套 **Windows 系统 OCR** 打码：内嵌 `dola-captcha-ocr.ps1`
```powershell
Add-Type -AssemblyName System.Runtime.WindowsRuntime
$null = [Windows.Storage.StorageFile, Windows.Storage, ContentType = WindowsRuntime]
$engine = [Windows.Media.Ocr.OcrEngine]::TryCreateFromUserProfileLanguages()
# BitmapDecoder 解码 → engine.RecognizeAsync → $result.Text
```
调用方式：`powershell.exe -NoProfile -ExecutionPolicy Bypass -File "dola-captcha-ocr.ps1" -Path "<png>"`
截图探针：`#captchaimg, img[src*="Captcha"], img[src*="captcha"]`；识别失败 2 次转人工。

### 2.3 补号：邮箱网页登录 + 2FA（用于托管邮箱/Gmail 收码）
日志原文 = 完整动作序列：
```
正在打开邮箱页读取验证码…        邮箱页没有账号输入框 / 没有登录按钮
填入邮箱验证码，点击下一步。      选择第一项：通过账号接收验证码。
填入两步验证码，点击下一步。      没有找到两步验证码输入框。
```
- 支持粘贴格式：**`账号----密码----秘钥`**（第三段是 TOTP 秘钥）
- 2FA 工具：`https://2fa.run/2fa/`（软件内提示"用粘贴的秘钥打开"）
- 邮箱面板（软件自带/自建）：`https://google111111.asia/`
  - 「安全查看验证码」：单邮箱登录看码；**批量**最多一次 50 条，支持一行一个纯邮箱或 `邮箱----密码----2FA`；
  - 反刷：**每分钟最多提交 2 次批量刷新**；批量走后台排队 + 读缓存。

## 3. ★核心：取CK「号厂」完整链路（可直接复刻）

### 3.1 配置面（Dola 分组 →「取CK设置」）
从字符串还原出的字段：

| 字段 | 证据字符串 |
|---|---|
| 代理 / 静态 IP | `请先在 Dola 分组「取CK设置」里填写代理`、`填写代理`、`填写静态`、`取CK静态IP`、`请先在取CK设置里填写静态 IP` |
| 邮箱前缀（≥8 字符） | `请先在取CK设置里填写邮箱前缀`、`字符不够，邮箱前缀至少需要 8 个字符`、`填写邮箱` |
| 域名 | `[取CK] 测试开始（不扣额度） 域名=` |
| 端口（自建收件服务） | `[取CK端口]` |
| 序号续编 | `序号从 001 开始`、`序号从  X 续编（已用到 ...）`、`[取CK] 前缀续编 `、`前缀 X 已使用，下次从 X 开始` |

即：**`<前缀>NNN@<域名>`**，NNN 从 001 递增续编，每号一次注册。

### 3.2 执行面（每号 5 步，全部有日志）
```
① 建实例 profile（代理/静态IP + 指纹）
② 打开 https://www.dola.com/            → 打开首页 HTTP ...
③ POST /passport/web/email/send_code/   → email=<前缀NNN@域名>
                                         发码成功 HTTP ... / 验证码已发送，等待邮箱 ...
④ 轮询收件箱：
   - tempmail.plus: GET /api/mails?email=<addr>&limit=5
   - 自建域名：GET http://<域名>:<取CK端口>/...（收件接口）
   正则 验证码[^0-9]{0,10}(\d{6}) 抽 6 位码
⑤ POST /passport/web/email/register_verify_login/  (code + password)
   → 注册成功 HTTP ...  cookie= N 条 耗时 N 秒 → 完成 id=...
```
**测试态**：`[取CK] 测试开始（不扣额度） 域名=` / `测试取CK不扣额度、不可导入实例` / `（测试号，请勿导入）`
**错误处理**：`发送过于频繁，请稍后再试或更换代理`、`失败次数过多，已停止`、`未验证账号（等 N 秒）`、`做最后验证`

### 3.3 池化面（这就是它们的「无限算力」本体）
| 机制 | 证据 |
|---|---|
| 一键批量取号 | `一键取CK`、`[一键取CK] 开始，共 N`、`一键取CK结束。成功 N 个，未取CK M 个`、`是否再次执行未取CK的实例？` |
| 暂停/续跑 | `已暂停（点「继续取CK」恢复）`、`停止取CK / 继续取CK / 开始取CK` |
| 新号写库 | `正在连接号池获取新账号…`、`已经获取新账号 -> ` |
| 换号 | `[换CK] 正在写入 Cookie 并刷新登录…`、`[换CK] 实例=<id> proxy=<proxy> 剩余额度=<n>`、`[换CK] 已清除档案内旧 Cookie，准备写入新号`、`[换CK] 清除旧 Cookie 失败`、`换CK成功 / 换CK失败` |
| 额度不足退号 | `取CK额度不足`、`[换CK] 退回取CK额度失败 hold=`、`取CK额度已用完。请打开个人中心，开通会员获赠额度，或充值取CK额度` |
| 只允许 Dola | `只有 Dola 实例可以换CK` |
| 配额 | `批量导出实例 CK`（`batch-ck-export-quota.txt`，**一天最多 20 个**） |
| 代理池 | 取CK**不走左栏代理**，走取CK设置里的代理/静态IP：`按主机、端口、账号、密码填写，取CK时不走左侧代理。必须开启 TUN 模式。`、`走科学上网地址。测试不扣额度。不要开 TUN。` |

## 10. ★迁移到「海外海螺 H3」：可执行方案

### 10.1 可迁移度评估

| dola 机制 | 能不能搬到海螺 H3 | 说明 |
|---|---|---|
| 邮箱+验证码注册 | **能（主路）** | H3 支持邮箱注册；已有 `mailfarm`（catch-all 域名 + IMAP 桥）+ 我们的 `号源-接码` |
| 前缀续编号厂 | **能** | 正是 R141 结论里"自建邮箱域名 + 脚本批量注册" |
| 邮箱码轮询抽 6 位数字 | **要改正则** | H3 邮件模板不同，需先采一封样本邮件 |
| 多实例独立 profile + 指纹 | **能** | H3 走 Firebase，指纹/时区/canvas noise 同样有用 |
| CDP `Network.setCookies` 注入 | **要换目标** | H3 登录态不是 cookie 而是 **Firebase idToken / refreshToken（localStorage）** |
| 一键换CK 池化调度 | **能（核心）** | 与我们在 :9940 池里的「最肥账号优先 → 402/401/429 换号」同构 |
| Google OAuth 自动化 + OCR | **能** | H3 是 Firebase（Google/Apple/Facebook），脚本几乎照抄 |
| 代理池 / 静态 IP | **能** | 海外站必须一号一出口 |

## 13. R143 增量：H3 号厂最后一公里 + 取号三件套适配层

### 13.1 重大修正：H3 发码接口的 `email` 走 **query**，不是 body（实测）

| 请求（hailuoai.video，自实现 yy 签名） | 结果 |
|---|---|
| POST `/v1/api/user/login/email/code`，body `{"email":x}` | 400 `请求异常，请检查请求参数` |
| POST `/v1/api/user/login/email/code?email=x`，空 body | **200** `code=1200019` + `debugInfo=email verification timing metadata unavailable` |
| POST `...?email=x` + body `{emailAddress}` / `{email,needCaptcha,captchaTicket}` | 400 |

=> 结论：`email` 必须放 **query**（body 里出现 email 反而被判参数非法）；空 body 时服务端已走到发码分支，只差一个 **timing/风控类字段**（"email verification timing metadata"）——这就是最后一道门。闭合办法见 13.4。

### 13.2 `scripts/mail-compat-server.js` 1.1.0（取号三件套适配层，双模式，已实测）

- `COMPAT_MODE=mailfarm`（默认）：上游 mailfarm(8099)/imap-bridge(8098)；`/v1/recipe`、`/v2/domains`、`/v1/mailboxes/acquire`、`/v1/mailboxes/{a}/code|messages`、`/api/mails`、`/api/mails/{id}` **全通**。
- `COMPAT_MODE=tempmail`：**白嫖 tempmail.plus 公开 API**（= dola 同款打法，无需 MX、无需自建邮服、零成本）；地址 = 前缀 + 序号(001起) + 4位随机 @ 域名池；**取号前先查收件箱是否干净，脏则换号**（避免读到别人的旧邮件）。
- 序号持久化 `state/mail-compat.json`（重启不重号）；`COMPAT_PROXY` 支持 CONNECT 出墙（实测 tempmail.plus 直连 1s / 走 127.0.0.1:10090 2s，均 200）。
- 取码正则（dola 同优先级）：`(?:code|Code|CODE)[^0-9]{0,20}(\d{6})` → `verification code...` → `(?:is|:)\s*(\d{6})` → `\b(\d{6})\b`

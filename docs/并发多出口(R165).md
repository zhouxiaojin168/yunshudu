# 并发多出口实测（R165）+ 出口体检（R166）

## 一、结论先行

| 结论 | 证据 |
|---|---|
| mihomo 单进程**无论选哪个组**，并发请求出口只有 **1 个 IP** | 「故障转移/自动选择/负载均衡」各 8 并发 → 去重后 **1 个** |
| 真并发多出口 = **多上游并行流** | `exit-multi health` → JP `213.218.254.4` + CN `114.66.16.225` **2 个不同出口同秒可用** |
| 3 个出口可**同时**跑真 token 验活 | 并行 5.6s 全部 `info/credit/equity = 200` |
| CN 出口**不能**做 H3 海外登录 | 17897：`hailuoai.video=200` 但 **google 不可达**（proxy 502 / TLS 被劫持） |

## 三、怎么扩到 N 个并发出口（按性价比排序）

1. **静态住宅 ISP × N**（最优）：`isp-onboard.js add 17901 "http://user:pass@host:port"` → 每个 ISP 端口 = 一个独立并发流
2. **海外 VPS × N**：`gw-deploy-linux.sh --host <IP> …` → `ysd-gw-client` 起一条隧道 = 一个独立并发流（本次已在 `114.66.16.225` 走通整条部署流水线）
3. **再开一个 mihomo 实例（可选）**：需要节点明文配置（server/password/sni）；把 103 个节点写成 `listeners: [{port, proxy: 节点名}]` 就能「一端口一节点」真并发（当前猫猫云配置为客户端加密存储，明文仅在进程内存，未落盘）

## 四、并发多出口命令速查

```bash
node scripts/exit-multi.js exits                       # 列出口
node scripts/exit-multi.js health                      # 并发体检（IP/国家/延迟/H3）
node scripts/exit-multi.js assign --in <accounts.jsonl> --exits 17899,17897
node scripts/exit-multi.js run --plan state/exit-plan.json        # 真跑
node scripts/exit-multi.js run --plan state/exit-plan.json --dry  # 只看编排
node scripts/isp-onboard.js verify <port>              # 单出口体检（静态/住宅/IDC/可达）
```

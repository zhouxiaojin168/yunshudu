## 1. flow2api 架构拆解（源码级证据）

仓库：`TheSmallHanCat/flow2api`（★3033，Python/FastAPI，2026-10-12 更新）
默认分支 `main`，72 个文件；核心在 `src/services/`。

| 文件 | 职责 | 关键实现 |
|---|---|---|
| `src/services/protocol_login.py` | **账号导入与校验** | 导出 Google Cookie → 过滤 `.google.com` 域 → 用 `curl_cffi`（`IMPERSONATE="chrome"`）打 `https://flow.google.com` → 从 bootstrap 里正则 `"oPEP7c"` 读登录邮箱 → 判定登录态 |
| `src/services/token_manager.py`（49200 字符） | **AT 自动刷新** | 每 token 一把 `asyncio.Lock`（按 token 维度，互不阻塞）、`_refresh_futures` 去重、`_at_validation_cache` 缓存校验、`_protocol_refresher_task` 后台常驻；默认刷新间隔 **120s**；`personal_project_pool_size` 默认 **4**（单 token 维护 4 个项目池轮换） |
| `src/services/load_balancer.py` | **负载均衡** | pending 计数 + 每 token 负载；`call_mode` = `default`(随机轮询) / `polling`(顺序轮询) |
| `src/services/proxy_manager.py` | **代理池** | 三档：token 协议代理 / 请求代理 / 媒体代理；`parse_proxy_line` + `normalize_proxy_url`；支持 HTTP/SOCKS5，一号一代理 |
| `src/services/recaptcha_runtime.py` + `browser_captcha*.py` + `twocaptcha.py` | **打码** | `yescaptcha/captcharun/twocaptcha/capsolver/ezcaptcha/browser/personal/remote_browser` 八种；v3 用 `RecaptchaV3TaskProxylessM1S9`（**强制 minScore 0.9**） |
| `src/core/account_tiers.py` | **账号分级** | `PAYGATE_TIER_NOT_PAID / ONE / TWO`（免费/Pro/Ultra）；按模型推断最低档位，不够就不派单 |
| `src/services/file_cache.py` | 结果缓存 | 默认 7200s |

`config/setting_example.toml` 关键项：
- `labs_base_url="https://flow.google.com"`、`image_launch_soft_limit=20`（单 token 并发上限）
- `error_ban_threshold = 3` → **连续 3 次错误即封该 token**（与我方「402/401/429 换号、最多 3 次」同构）
- 上游是 **Google Flow**（Veo / Nano Banana Pro），靠 Google 账号 Cookie 白嫖额度。

## 2. 映射到海外海螺（hailuoai.video）

**实测**：`hailuoai.video` 前端（Next.js，`prod-en-0.1.881`）的 auth 走 **Firebase**：
- JS 里出现 `identitytoolkit.googleapis.com`（Firebase Auth REST）
- 出现 `recaptchaKey` / `siteKey`（**reCAPTCHA** 防机器人）
- 登录入口只有 **Google / Apple / Facebook**（无手机、无邮箱密码）

所以映射关系：

| flow2api（Google Flow） | 海外海螺 H3（hailuoai.video） |
|---|---|
| Google Cookie（`.google.com`） | **Firebase ID Token + refreshToken**（登录后由 Firebase 下发） |
| `flow.google.com` bootstrap 取邮箱 | hailuo 自身 `/v1/api/user/info` 取身份 |
| reCAPTCHA v3 (minScore 0.9) | reCAPTCHA（同样需要打码，方法可复用 flow2api 的 provider 列表） |
| VideoFX Credits | hailuo credits（我方已在读） |
| AT 定时刷新 120s | Firebase refreshToken 换 ID Token（有效期 1h，refreshToken 长期） |
| 一号一代理 | 同 |
| tier 分级派单 | 海螺会员档位（免费/会员） |

**结论**：架构可 1:1 平移，**唯一改动是「凭证」从 Google Cookie 换成 Firebase 令牌**，以及注册环节从「Google 注册」换成「Firebase 登录（Google/Apple/FB）」。

## 3. 三个必须确认的前提（决定要不要做）

| # | 前提 | 现状 |
|---|---|---|
| P1 | 海外站**新账号是否送免费额度** | ❓未实测。国内站新号送 500 分；海外站待验证 |
| P2 | **注册是否需要手机验证** | ❓Firebase(Google/Apple) 通常不要手机，但海螺可能二次要求 |
| P3 | **额度是否按天发放** | ❓若按天送，才能做「签到补额」的无限算力；若一次性，则池子会枯竭 |

> 这三点只要有一项不成立，「无限算力」就打折 —— 必须先实测一次真号。

## 4. 可行性 / 成本 / 风险

| 维度 | 评估 |
|---|---|
| 技术难度 | 高（浏览器自动化注册 + Firebase 令牌管理 + 打码 + 代理池） |
| 关键依赖 | ① 能出墙的机器（注册用）② 住宅代理（1 号 1 IP，防关联封号）③ 打码余额（reCAPTCHA）④ Google/Apple 账号农场 |
| 单号成本 | 代理 IP 摊销 + 打码费 + 账号成本 ≈ **远高于**国内站的 0.4 元/号 |
| 封号风险 | 高（同 IP 多号、新号批量注册 = 典型风控特征） |
| 合规 | 只读研究 + 自有资产；不做第三方破坏 |

## 5. 建议（决策）

| 方案 | 取舍 |
|---|---|
| **A. 先做 P1/P2/P3 三点实测**（1 个真号，成本极低） | ✅ 推荐：先花小钱验证「海外站值不值得做」 |
| B. 直接照搬 flow2api 全量落地 | ❌ 前提未验证，可能白干 |
| C. 维持国内站为主，海外只做「备用上游」 | ✅ 稳 |
| D. 走 useapi.net 托管（flow2api 的赞助商，$15/月含海螺 MiniMax） | ⚠️ 省事但非自建，且是付费上游 |

> **王炸的建议**：先 A。海外站只要「有免费额度 + 按天发」，才具备做池子的经济性。
